# Speedtest CLI

Консольный скрипт на Node.js, который измеряет скорость скачивания: делает **10 последовательных HTTP-запросов** к указанному URL, дожидается полного тела ответа на каждый и выводит среднее время запроса, общий объём и скорость загрузки.

## Требования

- Node.js 18 или новее (используется встроенный `fetch`).

Проверка версии:

```bash
node --version
```

## Установка

```bash
git clone https://github.com/BymBu/internetMetrics
cd ИМЯ_РЕПО
```

Зависимостей нет — используются только встроенные модули Node.js.

## Запуск

```bash
node index.js <url>
```

Пример:

```bash
node index.js https://mirror.yandex.ru/ubuntu/ubuntu/ls-lR.gz
```

На Windows PowerShell URL с `?` нужно брать в кавычки:

```powershell
node index.js "https://example.com/file?x=1"
```

## Единицы измерения

| Метрика               | Единица                        |
|-----------------------|--------------------------------|
| Время одного запроса  | миллисекунды (мс)              |
| Среднее время ответа  | миллисекунды (мс)              |
| Скачанный объём       | мегабайты (МБ)                 |
| Затраченное время     | секунды (с)                    |
| **Скорость загрузки** | **мегабайты в секунду (МБ/с)** |

Где `1 МБ = 1024 × 1024 байт = 1048576 байт`.

## Как это работает

1. URL берётся из первого аргумента командной строки (`process.argv[2]`).
2. Выполняется `REQUESTS = 10` HTTP GET-запросов **последовательно** — каждый следующий стартует только после полного завершения предыдущего (`for` + `await` внутри).
3. Для каждого запроса:
   - фиксируется время старта через `performance.now()`;
   - дожидается полное тело ответа через `response.arrayBuffer()` (не `HEAD` и не только заголовки);
   - фиксируется время окончания и размер тела (`body.byteLength`).
4. Суммируются общий объём и общее время.
5. Среднее время запроса = `totalMs / REQUESTS`.
6. Скорость загрузки = `totalBytes / totalSeconds`, переведённая в МБ/с.

## Устранение неполадок

### `TypeError: fetch failed` / `ConnectTimeoutError` на Windows

Если все запросы падают с `UND_ERR_CONNECT_TIMEOUT`, хотя `curl` и браузер работают — причина обычно в перехвате TLS-трафика. Распространённые виновники:

- локальные прокси/VPN-клиенты (TgWsProxy, Radmin VPN и т.п.);
- антивирусы с проверкой HTTPS/SSL (Kaspersky, ESET, Avast, Dr.Web, Bitdefender);
- Windows Defender **Network Protection** / **Web Threat Defense**.

Что делать:

1. Добавить `node.exe` и папку проекта в исключения антивируса.
2. Временно отключить локальный прокси/VPN и проверить.
3. Временно отключить Defender Network Protection для диагностики:

```powershell
Set-MpPreference -EnableNetworkProtection Disabled
```

После проверки вернуть:

```powershell
Set-MpPreference -EnableNetworkProtection Enabled
```

Быстрая проверка, работает ли TLS из Node:

```bash
node -e "fetch('https://example.com').then(r => console.log('OK', r.status)).catch(e => console.log('ERR', e.cause?.code || e.message))"
```

### Зарубежные хосты недоступны

Если вы находитесь в РФ и зарубежные speedtest-хосты таймаутят — используйте российские зеркала. Проверенный пример, который стабильно отдаёт ~40 МБ:

```text
https://mirror.yandex.ru/ubuntu/ubuntu/ls-lR.gz
```
